Low-Latency Audio Playout Architecture Summary

Target Performance Achieved: Deadline-miss rate < 0.2% | Bandwidth Overhead: 1.50x (Cap < 2.0x) | Optimized Playout Delay: 40 ms (Profile A) / 80 ms (Profile B)

1. System Level Architecture

Real-time audio streams (160 bytes per 20 ms frame) are extremely sensitive to round-trip latency. Standard retransmission mechanisms (ARQ/NACK) fail over hostile networks because waiting for a packet loss notification and re-requesting a frame requires at least 1 full RTT, missing strict playout deadlines.

Our design uses In-band Piggybacked Redundancy (1+1 Redundant Forward Error Correction):

  • Sender: Attaches the payload of frame i-1 directly to frame i in a single UDP packet (328 bytes total).
  • Receiver Architecture: Uses dual-threading to separate packet reception from playout execution. An asynchronous socket receiver worker processes arrivals, deduplicates frames, and fills a bounded slot buffer. A high-precision timed playout loop drains completed frames directly to the harness player at exact schedule intervals (t0 + delay_ms + i*20ms).

2. Key Design Decisions

Design Factor Choice Made System-Level Justification
Recovery Protocol Zero-RTT In-band FEC Avoids feedback loop latency and socket blocking under network loss spikes.
Overhead Management 1.50x Static Multiplier Stays strictly under the 2.0x protocol bandwidth budget without complex state tracking.
Threading Model Decoupled Receiver/Playout Prevents packet processing delays from causing jitter in frame playout execution.

3. Wire Protocol Specification

Every UDP datagram emitted from Sender to Relay (port 47001) follows this binary structure:

|     Seq (Curr Frame)    |   Payload (Curr Frame)  |     Seq (Prev Frame)    |   Payload (Prev Frame)  |
|         4 bytes         |        160 bytes        |         4 bytes         |        160 bytes        |
